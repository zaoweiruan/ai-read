设计一套**分任务、可校验、可流式输出**的提示词体系。按功能拆成：全书概览、章节摘要、思维导图、引用问答、翻译/术语解释。

## 总体架构

推荐采用 **RAG + 结构化输出**：

1. 用户上传 EPUB/PDF，后端切分为章节和语义块。
2. 每个块生成 embedding，用于问答检索。
3. 摘要任务按章节逐层归纳：块摘要 → 章摘要 → 全书摘要。
4. 问答只允许基于检索到的原文片段回答，并给出章节定位。
5. 思维导图用 JSON 输出，前端渲染成树/图。



## 通用 System Prompt

```text
你是一名严谨的中文阅读助手，帮助用户快速、准确地理解书籍内容。

规则：
1. 只依据提供的书籍材料回答；材料不足时明确说明“原文未提供足够信息”。
2. 不编造事实、引用、页码、章节号或作者观点。
3. 区分作者观点、书中案例、你的解释；解释需明确标注为“补充说明”。
4. 保留关键术语的原文，首次出现时给出简明中文解释。
5. 输出使用简体中文，除非用户要求其他语言。
6. 回答应结构清晰、简洁，避免空洞的赞美和重复。
7. 涉及争议性观点时，呈现作者立场及其论证，而不替作者下绝对结论。
```

## 全书摘要 Prompt

```text
任务：基于以下书籍材料，生成一份适合 3–5 分钟阅读的全书导读。

输出格式：
# 一句话核心
用不超过 40 字概括全书核心命题。

# 本书解决什么问题
- 3–5 条，说明作者关注的问题和现实背景。

# 核心论点
- 3–6 条；每条包含：观点、支撑理由或案例、所在章节。

# 关键概念
| 概念 | 含义 | 为什么重要 |
|---|---|---|

# 阅读路径
- 按阅读顺序给出 3–5 个阶段，说明每阶段应关注的章节和问题。

# 常见误解
- 2–4 条，指出读者容易误读的地方。

材料：
{{book_context}}
```

要点：要求模型输出**章节定位**，便于前端跳转；限制条目数量，避免摘要膨胀。

## 章节摘要 Prompt

```text
任务：总结以下章节，帮助读者在 1 分钟内掌握要点。

输出 JSON：
{
  "chapter_title": "章节标题",
  "core_question": "本章试图回答的核心问题",
  "thesis": "作者的核心主张，不超过 60 字",
  "key_points": [
    {
      "point": "关键观点",
      "evidence": "论据、案例或推理",
      "location": "章节内大致位置或小节标题"
    }
  ],
  "terms": [
    { "term": "术语", "explanation": "简明解释" }
  ],
  "connections": "本章与全书主题或其他章节的关系"
}

规则：
- key_points 数量为 3–7。
- 不得添加材料中没有的案例或引用。
- 若材料是节选，明确说明结论可能不完整。

章节材料：
{{chapter_context}}
```

前端可把 JSON 渲染成卡片；若模型输出不稳定，使用 JSON mode / structured output，或先要求纯 JSON 再解析。

## 思维导图 Prompt

```text
任务：将以下书籍内容转换为思维导图，供前端渲染。

只输出 JSON，不要 Markdown、解释或代码块。

JSON schema：
{
  "title": "书名或主题",
  "children": [
    {
      "label": "一级主题",
      "children": [
        {
          "label": "二级主题",
          "children": [
            { "label": "具体观点或案例" }
          ]
        }
      ]
    }
  ]
}

约束：
1. 层级最多 4 层。
2. 每层节点不超过 7 个。
3. label 不超过 18 个汉字。
4. 优先呈现论证结构：问题 → 概念 → 论点 → 证据 → 结论。
5. 不得编造章节、人物、书名或数据。

书籍材料：
{{book_context}}
```

对长书不要一次生成全书导图；先逐章生成，再让模型合并：

```text
任务：将以下章节思维导图合并为全书思维导图。
保留各章核心逻辑，去重、归组，不新增原文没有的内容。

章节导图：
{{chapter_maps}}
```

## 引用式问答 Prompt

这是最关键的功能，应强制“检索增强 + 引用”：

```text
任务：根据检索到的书籍片段回答用户问题。

规则：
1. 只使用 <contexts> 中的内容；不要使用模型先验知识补充书中观点。
2. 每个实质性结论后标注来源，格式：[片段ID]。
3. 若片段之间冲突，说明冲突及各自出处。
4. 若无法回答，输出：
   {
     "answer": "提供的材料不足以回答该问题。",
     "citations": [],
     "follow_ups": ["可以尝试询问……"]
   }
5. 回答长度不超过 300 字，除非用户明确要求详细解释。
6. 最后给出最多 3 个后续问题。

输出 JSON：
{
  "answer": "回答正文，内嵌 [片段ID]",
  "citations": [
    { "id": "chunk_12", "chapter": "第2章", "quote": "不超过 50 字的原文摘录" }
  ],
  "follow_ups": ["问题1", "问题2"]
}

用户问题：
{{question}}

检索片段：
<contexts>
[chunk_12] {{chunk_text}}
[chunk_37] {{chunk_text}}
</contexts>
```

前端点击 `[chunk_12]` 时跳到原文位置，这是让产品显得可信的关键。

## 翻译 / 概念解释 Prompt

```text
任务：解释以下术语或段落。

输出：
1. 通俗解释：不超过 80 字。
2. 在本书语境中的含义：不超过 120 字。
3. 原文依据：引用提供的片段；无依据则写“材料中未提供直接依据”。
4. 相关概念：最多 3 个。

术语/段落：
{{target}}

上下文：
{{context}}
```

## 工程上的关键约束

- **分块**：按标题和语义切分，块大小约 800–1500 tokens，保留章节、页码、位置元数据。
- **两层摘要**：先做 chunk summary，再合并为 chapter summary，最后合成 book summary；不要依赖单次超长上下文。
- **结构化输出**：摘要、导图、问答都用 JSON schema 约束；解析失败时自动重试一次。
- **引用防幻觉**：要求 citation 的 `quote` 必须能在原 chunk 中精确匹配；匹配失败则丢弃该引用或要求重试。
- **流式体验**：全书导读和问答用 SSE 流式输出；思维导图可先生成大纲，再流式补全 JSON。
- **缓存**：同一本书、同一模型、同一 prompt 版本的章节摘要应缓存，避免重复计费。
- **Prompt 版本化**：把 prompt 存成独立模板文件，例如 `prompts/book_summary.v3.md`，记录模型、温度、schema 版本，便于回归测试。
