# 2026-10-22 设计｜阅读区连续滚动（跨章自动接续）v1.0

> 源：用户 2026-10-22 指令「内容显示窗口添加连续滚动功能，能自动进入相邻章节」（对前一版「连续改动」的澄清）。
> 范围：`src/components/content/BookContent.tsx`。

## 1. 行为

| 触发 | 行为 |
| --- | --- |
| 阅读区滚动到**底部**且仍在向下滚 | 自动进入**下一章**，新章从顶部开始（连续向下读） |
| 章节内容不足一屏（无法滚动） | 在底部继续**向下滚轮**即进入下一章 |
| 章节已是末章 | 不跳转（按钮同样禁用） |
| 向上方向 | **暂不自动跳章**（见 §5 遗留），使用「上一章」按钮 |

- **开关**：导航行新增「连续滚动」按钮（默认开启，激活态为 secondary；关闭后滚到底不再跳章）。
- **防抖/防回环**：切章后 1500ms 静默窗口 + 程序化滚动标记（400ms/6s 双档），屏蔽由内容重排与定位引发的滚动事件。
- **与已有能力一致**：章切换复用 `activeChapterId`（摘要/导图等联动照旧）；`下一章 / 上一章` 按钮保留。

## 2. 实现

- `scrollRef`（`.reader-content`）上绑定 `onScroll` 与 `onWheel`：
  - `onScroll`：到达底部（余量 24px）且 `scrollTop` 较上次**增大** → 下一章；到达顶部且**减小** → 上一章。
  - `onWheel`：底部继续向下滚（`deltaY > 0`）→ 下一章；顶部继续向上滚（`deltaY < 0`）→ 上一章（覆盖短章节无法滚动的情况）。
- 状态与引用：`contScroll`（开关）、`lockUntilRef`（静默窗口）、`programmaticRef`（程序化滚动标记）、`lastTopRef` / `dirRef`（滚动方向判定）、`localChapterId`（阅读区当前章的本地镜像）。
- 切章时同时写入 store（`useBookStore.setState`）与本地镜像，确保阅读区立刻切换；本地镜像仅在**用户显式点击章节**（store 的 `chapterRequest` 计数变化）时清除。
- 滚轮与滚动同时命中时，靠静默窗口与程序化标记避免连跳两章。

## 4. 顺带修复的底层问题（重要）

排查过程中发现并修复了**两个 dev 期基础问题**（会放大各种「点了没反应 / 状态错乱」现象）：

1. **zustand store 多实例**：Vite HMR 会给失效模块加 `?t=` 时间戳，导致同一 store 在应用中出现多个实例，组件之间读写不同实例。修复：四个 store（book / settings / reader / prompt）改为挂在 `globalThis` 的**单例**（首次创建后复用）。
2. **模块缓存陈旧**：`server.headers` 增加 `Cache-Control: no-store`，避免浏览器长期缓存带时间戳的旧模块。

## 5. 遗留

- **向上自动回上一章**暂不提供：dev 环境下「持久化回填 + Fast Refresh 保留订阅」会把刚切换的章节写回旧值，导致刚跳到上一章即被弹回（生产构建无此问题）。为避免交付不稳定行为，向上方向改用「上一章」按钮。

## 6. 验收

- 长章节：滚到底 → 自动进入下一章且从顶部开始；短章节：底部继续下滚 → 进入下一章。
- 连续滚动关闭后：滚到底不跳章。
- 首/末章不越界；切章后不因程序化滚动二次跳章。
- typecheck / build 绿；写后必查。
