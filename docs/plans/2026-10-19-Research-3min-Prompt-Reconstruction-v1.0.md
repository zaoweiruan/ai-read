## 2. 输出 Schema（实证字段）

整书总结输出 = 以下字段集合（顺序与渲染分区）：

```text
{
  summary: 1-3 句全书概括,
  gains: 3 条「你能获得」bullets,
  chapters: [                       // 章节重点：每章一节
    { title: 编号小节标题,
      points: 3-5 条 bullets,
      explain: 详细解释（2-4 句）,
      example: 举例（可缺省）,
      advice: 行动建议（可缺省） }
  ],
  faq: [ { q, a } x 3-5 ],          // Q:/A: 术语与核心任务问答
  targetAudience: 1 段（目标读者）,
  author: 1 段（作者背景）,
  context: 1 段（写作背景/历史背景）,
  minutes: number 一位小数（阅读时长估算）
}
```

中间层（样本 B 泄露）先用 markdown 草稿生成：

```markdown
## {书名} - 内容总结
### 总结
…
### 你能获得
- …
### 核心内容
#### 1. {小节}
- …
详细解释：…
举例：…
行动建议：…
```

## 3. 重建 Prompt（非原文）

### P1 整书总结（book summary）

```text
你是专业的书籍总结助手。请阅读全书内容，用中文按以下结构输出：

1. 「{书名} 讲了什么」：1-3 句概括全书核心。
2. 「你能获得」：恰好 3 条，每条以 - 开头，说明读者收益。
3. 核心内容：将全书拆分为若干编号小节（1. 2. 3. …，对应章节或主题），每小节包含：
   - 3-5 条要点 bullets；
   - 「详细解释：」2-4 句展开；
   - 「举例：」1 句（有合适例子时给出）；
   - 「行动建议：」1 句（对读者有可执行建议时给出）。
4. 目标读者：1 段，说明这本书适合谁。
5. 作者背景：1 段，基于书中可得信息介绍作者（不确定的信息不要编造）。
6. 写作背景：1 段，说明本书的创作背景与时代语境。
7. FAQ：3-5 组「Q: …」/「A: …」，覆盖书中关键术语与核心问题。
8. minutes：估计普通读者读完全书摘要所需的分钟数（一位小数）。

约束：只使用书中内容；缺失信息不补造，直接省略该字段；输出纯文本，不使用表格。
```

### P2 章节总结（chapter summary，章节摘要页签）

```text
你是专业的书籍章节总结助手。请阅读所给章节内容，用中文输出：
1. 一句话概括本章主旨。
2. 3-5 条本章要点 bullets。
3. 「详细解释：」2-4 句展开本章论证/情节脉络。
4. 「举例：」本章中最有代表性的 1 个例子或情节（可缺省）。
5. 「行动建议：」读者可采取的一条可执行建议（可缺省）。
约束：只使用本章内容，不引入其他章节信息；缺失信息不补造。
```

### P3 大纲（outline，大纲页签）

```text
你是专业的书籍结构分析助手。请基于全书目录与内容，用中文输出层级大纲：
- 一级节点：章/部分标题；
- 二级节点：该章 2-4 个关键小节或论点；
- 每个节点后可附 ≤15 字说明。
约束：结构忠实于原书目录，不合并、不虚构章节；输出 JSON（{topic, children[]}）或缩进文本。
```

### P4 思维导图（mindmap，思维导图页签）

```text
你是专业的思维导图生成助手。请基于全书内容生成思维导图，输出严格 JSON：
{ "topic": "书名或核心主题", "children": [ { "topic": 分支主题, "children": [...] } ] }
约束：2-4 层；一级分支 4-8 个；节点文字 ≤20 字；不使用 id/detail 等额外字段；只输出 JSON。
```

### P5 翻译（translation，翻译页签，仅标注）

原文 → 中文，保持段落与语气；专有名词保留原文并首次出现时附中文。

## 4. 无法恢复的部分

- 系统提示词（角色设定、模型、温度、采样参数）——纯服务端；
- 精确措辞与 few-shot 示例（如有）；
- 分块/截断策略（长书如何切分喂给模型）——样本显示章节粒度稳定，推测按章切分 + 汇总两阶段（与「章节摘要 → 整书摘要」两段结构吻合）；
- 会员共享总结（会员总结共享）的聚合逻辑。

## 5. 对 ai-read 的落地建议

- ai-read 现有 `chapter-mindmap` / `book-mindmap` / `summary` 三模式可与 P1-P4 对齐：
  - `summary`（文字总结）采用 P2 结构（要点 + 详细解释 + 举例 + 行动建议）替代纯段落总结；
  - 新增整书「章节摘要 + 目标读者/作者/背景/FAQ」分区展示（ResultView 扩展）；
  - mindmap prompt 对齐 P4（严格 JSON、≤20 字、2-4 层）——与现有 `safeJson + normalizeNodes` 防御链路兼容。
- 以上属需求变更，需先对照 `docs/spec/ai-read 需求.md` 评估，不在当前阶段 3（布局）范围内。
